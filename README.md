# GaboxAPI

The backend behind my portfolio site. Instead of hardcoding projects and certifications into the frontend, everything lives here so I can update the site without touching frontend code.

FastAPI + PostgreSQL, deployed on Vercel. Full multilingual support — projects, courses and certifications keep their titles and descriptions in separate translation tables, which is what makes the three-language frontend work.

🌐 **Live:** [api.gabrielmayorga.dev](https://api.gabrielmayorga.dev) — `/docs` has the interactive Swagger UI.

**Frontend repo:** [github.com/Gaboxqc/Portfolio](https://github.com/Gaboxqc/Portfolio)

---

## Stack

- **FastAPI** — routing, validation and automatic OpenAPI docs
- **SQLModel** — ORM and Pydantic schemas in one place
- **PostgreSQL** — the database
- **Alembic** — migrations (sole owner of the schema)
- **pytest / ruff / black** — tests and linting, run in CI
- **Vercel** — serverless deployment

---

## Layout

```
api/
  core/          Cross-cutting infrastructure, shared by every project module
    config.py      Typed settings; fails fast on missing env vars
    database.py    Engine and session; pool chosen by environment
    security.py    X-API-KEY validation
    errors.py      Constraint violations -> 409 / 422 instead of 500
    deps.py        Pagination, get_or_404, eager loading, LIKE escaping
    crud.py        Generic CRUD router for simple lookup resources
    health.py      Index and readiness endpoints
  portfolio/     Portfolio domain — models and routers
  statpitch/     Football prediction domain (being reworked separately)
tests/           pytest suite, runs against in-memory SQLite
alembic/         Migrations
main.py          create_app() factory
```

## Running it locally

Requires Python 3.12+ and a PostgreSQL database.

```bash
git clone https://github.com/Gaboxqc/GaboxAPI.git
```

Create and activate a virtual environment, then install the dependencies with [uv](https://docs.astral.sh/uv/):

```bash
uv pip install -r pyproject.toml --extra dev
```

This installs what `pyproject.toml` declares without building the project itself. The repo is a flat layout rather than an installable package, so `main` and `api` are imported from the working directory — `pytest` is configured with `pythonpath = ["."]` to match. CI installs exactly the same way.

Copy the example environment file and fill it in:

```bash
cp .env.example .env
```

Run the migrations:

```bash
alembic upgrade head
```

Start the server:

```bash
uvicorn main:app --reload
```

API at `http://localhost:8000`, docs at `http://localhost:8000/docs`.

## Tests

```bash
pytest
```

Every test runs against a fresh in-memory SQLite database with foreign keys enabled — no PostgreSQL needed, and `conftest.py` pins `DATABASE_URL` before the app is imported so a value in your shell can never point a test run at a real database.

Lint and format:

```bash
ruff check .
```

```bash
black api tests main.py
```

CI runs all three on every push and pull request.

## Endpoints

`GET` is public. Everything that writes needs an `X-API-KEY` header.

### Health

| Method | Endpoint | Notes |
|---|---|---|
| `GET` | `/` | Service index |
| `GET` | `/health` | 200 only when the database is reachable, else 503 |

### Lookup resources

Tags, academies, categories, project types, difficulty levels and languages all share one contract, generated by `crud_router`:

| Method | Endpoint |
|---|---|
| `GET` | `/portfolio/{resource}` — paginated via `offset` and `limit` |
| `GET` | `/portfolio/{resource}/{id}` |
| `POST` | `/portfolio/{resource}` 🔒 |
| `PATCH` | `/portfolio/{resource}/{id}` 🔒 |
| `DELETE` | `/portfolio/{resource}/{id}` 🔒 |

where `{resource}` is one of `tags`, `academies`, `categories`, `project-types`, `difficulty-levels`, `languages`. Languages are keyed by their two-letter `code` rather than a numeric id.

### Projects

| Method | Endpoint | Notes |
|---|---|---|
| `GET` | `/portfolio/projects` | Filter by `is_main`, `search`, `project_type_id`, `difficulty_level_id`, `tag_id` |
| `GET` | `/portfolio/projects/{id}` | |
| `POST` | `/portfolio/projects` | 🔒 |
| `PATCH` | `/portfolio/projects/{id}` | 🔒 |
| `DELETE` | `/portfolio/projects/{id}` | 🔒 |

`project_type_id`, `difficulty_level_id` and `tag_id` accept repeats (`?tag_id=1&tag_id=2`) and match any of them.

### Certifications and courses

Same five routes under `/portfolio/certifications` and `/portfolio/courses`. Certifications filter by `year`, `academy_id`, `category_id` and `tag_id`; courses by `category_id` and `tag_id`.

### Translations

Each of the three resources above carries per-language content:

| Method | Endpoint |
|---|---|
| `GET` | `/portfolio/{resource}/{id}/translations` |
| `GET` | `/portfolio/{resource}/{id}/translations/{language_code}` |
| `POST` | `/portfolio/{resource}/{id}/translations` 🔒 |
| `PATCH` | `/portfolio/{resource}/{id}/translations/{language_code}` 🔒 |
| `DELETE` | `/portfolio/{resource}/{id}/translations/{language_code}` 🔒 |

## How the data is structured

Each main resource has a core record with the metadata, a translations table for the multilingual content, and a join table for tags.

```
Project
  ├── ProjectTranslation   (title + description per language)
  ├── Tags                 (many-to-many)
  ├── ProjectType
  └── DifficultyLevel

Certification / Course follow the same idea
  ├── Translation
  ├── Tags
  ├── Academy
  └── Category
```

### Attaching tags

Create and update payloads take a write-only `tag_ids` array. The tag links live
in a join table, so the routers translate these ids into rows rather than
storing them on the record.

```jsonc
// POST /portfolio/projects
{ "year": 2026, "project_type_id": 1, "difficulty_level_id": 2, "tag_ids": [3, 7] }
```

On `PATCH` the field distinguishes two cases that a plain list cannot:

| `tag_ids` | Effect |
| --- | --- |
| omitted / `null` | Tags are left untouched |
| `[]` | Every tag is removed |
| `[3, 7]` | Tags are replaced with exactly these |

Unknown ids are rejected with a `422` naming them, rather than being dropped
silently — a typo should not look like a save that quietly lost a tag.
Duplicates are collapsed.

### Pagination totals

Every list endpoint returns an `X-Total-Count` header with the number of rows
matching the current filters, ignoring `offset` and `limit`, so a client can size
a pager without a second request.

A header rather than a `{items, total}` envelope, because the public frontend
already consumes bare arrays. The header is listed in the CORS `expose_headers`,
without which a browser receives it but JavaScript cannot read it.

## Errors

Responses use FastAPI's `{"detail": ...}` shape throughout.

| Status | Meaning |
|---|---|
| `401` | Missing or invalid `X-API-KEY` |
| `404` | Record does not exist |
| `409` | Duplicate value, or deleting a record another record still references |
| `422` | Invalid payload, or a reference to a record that does not exist |

Database errors never surface as 500s or leak SQL — the raw error goes to the log, the client gets one of the above.

## Auth

Write endpoints accept **either** of two credentials.

### 1. Master key — for scripts and machine callers

```
X-API-KEY: your-secret-key
```

The key comes from `API_MASTER_KEY`. It is compared in constant time, and the app refuses to start if the variable is missing, so write access can never be accidentally left open.

### 2. Admin session — for the dashboard

The master key must never reach a browser, so the admin dashboard logs in with a password instead and receives a server-side session.

Create the account first (there is no signup endpoint, on purpose):

```bash
alembic upgrade head
python -m scripts.create_admin
```

Then:

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/auth/login` | Exchange username + password for a session cookie |
| `POST` | `/auth/logout` | Revoke the current session |
| `GET` | `/auth/me` | Describe the logged-in admin |
| `GET` | `/auth/sessions` | List active sessions, to spot one you do not recognise |

How it works, and why:

- **argon2id** password hashing — memory-hard, so GPU cracking is expensive rather than merely slower.
- **Opaque session tokens, stored as SHA-256 hashes.** Not JWTs: a JWT cannot be revoked, so a stolen one stays valid until it expires. A row here can be deleted, and the lookup is free because every request already reaches Postgres. Only the hash is stored, so a database leak hands over no live sessions.
- **`httpOnly; Secure; SameSite=Lax` cookie.** JavaScript cannot read it, so XSS cannot exfiltrate the session. Lax is enough because the API and the site share a registrable domain.
- **CSRF**: unsafe methods must echo the readable `gabox_csrf` cookie in an `X-CSRF-Token` header. It is compared against the value held server side, so an attacker who can only write cookies still cannot pass it. Master-key callers are exempt — a browser never attaches a custom header on its own.
- **Lockout**: failed attempts are counted in the database, per username *and* per IP, so neither rotating usernames nor spraying from one address slips through. An in-memory counter would enforce nothing on serverless, where every invocation is a fresh process.
- **No user enumeration**: an unknown username and a wrong password return an identical response, and the unknown-username path burns the same CPU on a throwaway hash so timing does not leak either.

Changing a password (`--reset`) revokes every existing session, so a reset after a suspected compromise actually locks the attacker out.

## Deploying

`vercel.json` is already set up. Connect the repo on Vercel and add `DATABASE_URL` and `API_MASTER_KEY` as environment variables. Run `alembic upgrade head` against the production database, then `python -m scripts.create_admin` once to create the admin account.

Migrations are not run automatically — apply them before deploying a schema change:

```bash
alembic upgrade head
```

The engine drops its connection pool when `VERCEL` is set, since each invocation is a fresh process that could never reuse a pooled connection. Point `DATABASE_URL` at your provider's **pooled** endpoint.

CORS defaults to `localhost:5173`, `localhost:8000` and the portfolio domains; override with `CORS_ORIGINS`.
